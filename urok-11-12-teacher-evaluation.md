# Урок 11-12. Принципи оцінювання учнівських HTML + CSS проєктів (для викладача)

## Для кого цей матеріал
- Для викладача
- Вік учнів: 10–13 років
- Рівень учнів: початковий
- Формат: методичний матеріал для перевірки робіт
- Технології, які оцінюються: `HTML` + `CSS` + базова публікація через `GitHub Pages`

---

## Мета цього матеріалу

Цей файл потрібен не для проведення звичайного уроку, а для того, щоб викладач міг:
- оцінити учнівські роботи за зрозумілими критеріями;
- побачити, що вважати сильною роботою, а що — слабкою;
- відрізняти технічні помилки від дрібних недоліків;
- виставляти оцінку не "на око", а за конкретними ознаками;
- дати учню корисний зворотний зв'язок.

---

## Загальна ідея оцінювання

На цьому етапі курсу важливо оцінювати не лише красу сайту, а й:
- чи розуміє учень структуру сторінки;
- чи вміє працювати з HTML і CSS;
- чи може створити завершений невеликий проєкт;
- чи здатен пояснити, що саме він зробив;
- чи зміг опублікувати сторінку на хостинг.

Для дітей 10–13 років важливо не карати за кожну дрібну технічну неточність. Головне — бачити:
- логіку роботи;
- охайність;
- самостійність;
- завершеність проєкту.

---

## Що саме доцільно оцінювати

Підсумкова учнівська робота може включати:
- сторінку з `header`, `main`, `section`, `footer`;
- меню;
- картки через `Flexbox`;
- форму;
- базове оформлення через `CSS`;
- публікацію сайту на `GitHub Pages`.

---

## Основні критерії оцінювання

### 1. Структура HTML
Оцінюється:
- чи є логічна побудова сторінки;
- чи використовуються правильні теги;
- чи не хаотично побудований документ;
- чи є основні частини сторінки.

### 2. Охайність і порядок у коді
Оцінюється:
- чи є відступи;
- чи зручно читати код;
- чи не змішані випадково різні частини сторінки;
- чи закриті теги.

### 3. CSS-оформлення
Оцінюється:
- чи сторінка має завершений вигляд;
- чи використані кольори, відступи, фони, рамки;
- чи елементи не "злипаються";
- чи є візуальна акуратність.

### 4. Практична завершеність роботи
Оцінюється:
- чи сайт виглядає як завершена сторінка;
- чи є зміст, а не лише порожні блоки;
- чи виконано основне завдання уроків.

### 5. Самостійність і розуміння
Оцінюється:
- чи може учень пояснити, що таке `header`, `section`, `form`, `Flexbox`;
- чи може сказати, де в нього HTML, а де CSS;
- чи розуміє, навіщо потрібні основні елементи.

### 6. Публікація на GitHub Pages
Оцінюється:
- чи сайт реально викладено;
- чи відкривається посилання;
- чи вивантажені правильні файли;
- чи працює оформлення після публікації.

---

## Проста рубрика оцінювання (10 балів)

### Критерій 1. HTML-структура — 0–2 бали

**0 балів**
- структура сторінки майже відсутня;
- теги використовуються випадково;
- сторінка зібрана неправильно.

**1 бал**
- є частина потрібних тегів;
- структура зрозуміла лише частково;
- є помилки, але загальна ідея проглядається.

**2 бали**
- структура логічна;
- є основні частини сторінки;
- HTML зібраний правильно або майже правильно.

---

### Критерій 2. Охайність коду — 0–2 бали

**0 балів**
- код дуже важко читати;
- немає відступів;
- багато хаосу.

**1 бал**
- код читається частково;
- є окремі помилки в оформленні;
- місцями структура неакуратна.

**2 бали**
- код охайний;
- відступи правильні;
- файл читається легко.

---

### Критерій 3. CSS-оформлення — 0–2 бали

**0 балів**
- стилів майже немає;
- сторінка виглядає сиро.

**1 бал**
- базові стилі є;
- видно спробу оформлення;
- але сторінка ще проста.

**2 бали**
- сторінка виглядає акуратно;
- є кольори, відступи, оформлення блоків;
- видно завершений результат.

---

### Критерій 4. Практичне завдання / зміст — 0–2 бали

**0 балів**
- робота не завершена;
- сторінка порожня або майже порожня.

**1 бал**
- виконано частково;
- є зміст, але не все завершено.

**2 бали**
- робота завершена;
- є текст, блоки, картки або форма;
- сторінка виглядає як маленький сайт.

---

### Критерій 5. Самостійність і розуміння — 0–1 бал

**0 балів**
- учень не може пояснити, що він зробив.

**1 бал**
- учень розуміє основні елементи своєї роботи і може коротко їх пояснити.

---

### Критерій 6. Публікація на GitHub Pages — 0–1 бал

**0 балів**
- сайт не опублікований або посилання не працює.

**1 бал**
- сайт опублікований і відкривається.

---

## Підсумкова шкала

- **9–10 балів** — відмінна робота
- **7–8 балів** — хороша робота
- **5–6 балів** — робота середнього рівня
- **3–4 бали** — слабка робота, але є спроба
- **0–2 бали** — робота майже не виконана

---

## Більш м'яка шкільна інтерпретація рівнів

### Початковий рівень
Учень:
- виконав тільки частину завдання;
- має труднощі зі структурою HTML;
- потребує постійної допомоги.

### Середній рівень
Учень:
- розуміє базові теги;
- може створити сторінку за зразком;
- допускає помилки, але загалом виконує завдання.

### Достатній рівень
Учень:
- самостійно збирає невеликий сайт;
- використовує HTML і CSS усвідомлено;
- має охайну й завершену роботу.

### Високий рівень
Учень:
- виконує роботу самостійно;
- додає власні ідеї;
- має охайний код і акуратний дизайн;
- публікує сайт без значних труднощів.

---

## Що вважати сильним результатом

Сильна учнівська робота — це коли:
- є логічна структура сторінки;
- є охайне меню;
- є блоки або картки;
- є форма;
- сторінка виглядає акуратно;
- сайт відкривається за посиланням;
- учень може коротко пояснити свій код.

Навіть якщо робота не ідеальна, але учень:
- зробив її сам;
- розуміє свій результат;
- довів сайт до завершення,
то це вже хороший показник.

---

## Що вважати слабким результатом

Слабка робота — це коли:
- є лише випадковий текст без структури;
- HTML і CSS змішані хаотично;
- сторінка незавершена;
- немає логіки;
- сайт не відкривається або не оформлений;
- учень не розуміє, що написав.

---

## Типові помилки учнів

### У HTML
- забули закрити тег;
- переплутали вкладення елементів;
- написали текст поза потрібними блоками;
- не використовують `header`, `main`, `section`, `footer`.

### У CSS
- забули крапку перед класом;
- написали властивість без двокрапки;
- не закрили фігурну дужку;
- підключили не той файл стилів;
- ввімкнули `Flexbox` не на тому блоці.

### Під час GitHub Pages
- не завантажили `index.html`;
- забули `style.css`;
- не ввімкнули Pages;
- дали неправильне посилання;
- не дочекалися, поки сторінка опублікується.

---

## Як давати зворотний зв'язок учню

Добре працює така схема:

### 1. Спочатку похвалити
Наприклад:
- "У тебе вже вийшла справжня структура сайту."
- "Мені подобається, що ти зробив охайні картки."
- "Ти добре попрацював із кольорами."

### 2. Потім назвати 1–2 помилки
Наприклад:
- "Треба закрити один тег `div`."
- "Меню ще не стоїть в один ряд."
- "Сайт треба ще опублікувати."

### 3. Наприкінці дати чіткий наступний крок
Наприклад:
- "Додай `display: flex` для меню."
- "Підключи `style.css`."
- "Покажи мені посилання на GitHub Pages."

## Готовий шаблон короткого коментаря до роботи

### Якщо робота сильна
"Робота виконана добре. Є правильна структура сторінки, охайне оформлення, картки та форма. Сайт виглядає завершеним і відкривається за посиланням."

### Якщо робота середня
"Робота виконана частково правильно. Структура сторінки є, але потрібно покращити оформлення і ще уважніше попрацювати з CSS та акуратністю коду."

### Якщо робота слабка
"Робота поки що незавершена. Потрібно доопрацювати структуру HTML, виправити помилки в CSS і довести сторінку до завершеного вигляду."

---

## Підсумок для викладача

На цьому етапі найважливіше не шукати ідеальний професійний код, а перевірити:
- чи дитина зрозуміла логіку створення сторінки;
- чи вміє зібрати свій маленький сайт;
- чи може оформити його через CSS;
- чи здатна показати результат у вигляді опублікованої сторінки.

Якщо учень зробив простий, але завершений і зрозумілий сайт — це вже дуже хороший результат для цього віку.
